# コードレビュー＆自動修正

引数で指定されたファイルまたは現在の変更をレビューし、指摘事項をすべて修正してください。

## レビュー対象
$ARGUMENTS

引数が指定されていない場合は `git diff HEAD` の変更内容をレビューしてください。

---

## Phase 1: レビュー

以下の観点で日本語でレビューを行い、問題点を重要度別 (🔴 Critical / 🟠 High / 🟡 Medium / 🟢 Low) に分類してください。

### 1. 機密情報の有無
以下のパターンを検索し、ファイル内にハードコードされていないか確認してください:
- APIキー・シークレットキー・アクセストークン (例: `sk-`, `AKIA`, `ghp_`, `xox`)
- パスワード・認証情報 (例: `password=`, `passwd=`, `secret=`)
- 接続文字列・DSN (例: `mysql://`, `postgres://`, `mongodb://`)
- 秘密鍵・証明書 (例: `BEGIN PRIVATE KEY`, `BEGIN RSA PRIVATE KEY`)
- 環境変数の値が直書きされている箇所 (`.env` に委譲すべき値)
- `.env` / `.env.*` ファイル自体がコミット対象になっていないか (`git ls-files` で確認)
- `.dockerignore` / `.gitignore` で機密ファイルが除外されているか

機密情報が見つかった場合は **必ず 🔴 Critical** として報告し、修正フェーズで即座に対処してください。

### 2. バグ・ロジックエラー
- 境界値・エッジケースの未処理
- null/undefined の未チェック
- 非同期処理の競合状態

### 3. セキュリティ
- 認証・認可の漏れ
- 入力値のバリデーション不足
- SQLインジェクション / XSS / CSRF のリスク

### 4. パフォーマンス
- N+1 クエリ
- 不必要な再レンダリング (React)
- メモリリーク

### 5. コード品質
- TypeScript の型安全性 (any の使用など)
- 関数・変数の命名
- 重複コード・DRY 原則違反
- コンポーネントの責務分離

### 6. プロジェクト固有
- Laravel のベストプラクティス遵守 (apps/api)
- Next.js / React のベストプラクティス遵守 (frontend)
- API レスポンス形式の一貫性

## レビュー出力フォーマット

各問題について以下の形式で出力してください:

```
[重要度] ファイル名:行番号
問題: <問題の説明>
修正案: <具体的な修正方法>
```

最後に全体的な所感と良かった点もまとめてください。

---

## Phase 2: 自動修正

レビューで指摘したすべての問題を、重要度の高い順 (🔴→🟠→🟡→🟢) に修正してください。

### 修正ルール
- **🔴 Critical の機密情報**: ハードコードされた値を環境変数参照に置き換え、`.env.example` にキー名のみ追記する
- **🔴 / 🟠**: 必ず修正する
- **🟡**: 修正する (ただし既存の動作を壊さない範囲で)
- **🟢**: 修正する (スコープが大きい場合はコメントで TODO を残してもよい)
- 修正はファイルを直接編集し、変更内容を簡潔に説明する
- 修正後に変更箇所の一覧を表示する

### 修正完了後
修正した項目を表形式でまとめてください:

| 重要度 | ファイル | 内容 | 対応 |
|--------|---------|------|------|
| 🔴 | ... | ... | 修正済 |
